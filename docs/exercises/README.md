# 과제 해설 안내

이 영역은 각 챕터의 **실습 과제**와 **심화 과제**를 먼저 시도한 뒤 선택적으로 확인하는 공간입니다. 본문을 순서대로 읽을 때는 수행 예시나 완성 코드가 자동으로 노출되지 않습니다.

## 이용 순서

1. 챕터 본문에서 과제의 목표와 조건을 확인합니다.
2. 본문 예제를 복사한 별도 파일이나 브랜치에서 직접 구현합니다.
3. 막히면 해당 과제의 **힌트**만 먼저 확인합니다.
4. 구현을 마친 뒤 **확인 기준**과 비교합니다.
5. 마지막에 수행 예시와 전체 코드를 읽고 설계 차이를 비교합니다.

## 과제 ID 규칙

과제 ID는 `P{파트}-C{챕터}-{종류}{번호}` 형식을 사용합니다.

- `P1-C06-P1`: Part 1, 06 챕터의 첫 번째 실습 과제
- `P1-C06-A1`: Part 1, 06 챕터의 첫 번째 심화 과제
- `P2-C13A-P3`: Part 2, 13A 챕터의 세 번째 실습 과제

`P`는 Practice, `A`는 Advanced를 뜻합니다. 챕터 안에서 과제 문장을 다듬더라도 기존 ID는 바꾸지 않습니다. 과제를 제거해야 한다면 ID를 다른 과제에 재사용하지 않습니다.

## 해설 작성 원칙

- 수행 예시는 유일한 정답이 아니라 요구사항을 만족하는 한 가지 구현입니다.
- 값만 변경하는 관찰 과제는 예상 결과와 확인 방법을 중심으로 설명합니다.
- 설계형 과제는 결과 코드뿐 아니라 선택 기준과 대안의 장단점을 설명합니다.
- 코드 과제의 전체 소스는 독립 실행 또는 자동 테스트가 가능해야 합니다.
- 이후 챕터의 본문이 앞선 과제와 비슷한 코드를 사용하면, 해설에서 중복 관계를 명시합니다.

전체 진행 상황은 [과제 해설 coverage](coverage.md)에서 확인할 수 있습니다.
